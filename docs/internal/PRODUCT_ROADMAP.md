# 移动端任务路线

跨端里程碑权威计划仍见[电脑仓库专项计划](https://github.com/wuqiuwangtian/TravelFlow-AI/blob/main/docs/internal/MOBILE_CONTINUITY_PLAN.md)，本页只安排移动侧工作。用户已确认移动实现主线及P1设计入口，不代表跨端P0全部门槛通过；当前事实见[PROJECT_STATUS](PROJECT_STATUS.md)。

1. **P0主线决策已记录，正式适配门槛保留。** [框架决定](ANDROID_FRAMEWORK_REVIEW.md)记录用户2026-11-14确认以固定Capacitor8.6.0为实现起点，分离TS业务与Android存储／凭据／传输，并进入P1设计。用户已确认分级支持，优先对有持续更新来源的环境作正式承诺，旧设备继续兼容验证，保留全部目标能力、暂不改变minSdk。预设服务商＋高级自定义地址、默认HTTPS及按目标隔离凭据已确认；用户主动调用不反复认证、已发请求可继续、锁屏不自动新发也已确认，后台存活仍未验证。不能把框架确认等同正式传输／凭据已可采用或批准发布。

   历史系统／引擎／ABI组合、单台ARM64真机、存储／TLS／DNS／网络丢失与严格Private DNS拒绝证据统一见[PROJECT_STATUS](PROJECT_STATUS.md)，构建／模拟器／真机／真实供应商／用户验收分别记录，不在路线图重复完整矩阵。Chrome旧官方更新线结束对支持承诺的影响见采纳提案；其他提供方须另核实，不能以能安装、签名一致或功能检测替代维护与行为证据。API35恢复首请求失败及ADB偶发采样失败保持未定因，不无界重跑相同条件，也不据此宣布修复。

   采用前仍需正式模块、系统解析／辅助进程失败路径、代理／Private DNS与动态配置、真实供应商、凭据生命周期／锁屏、数据迁移／存储失败等验证；原ProbeStream阻塞DNS及当前实验拒绝策略不能升格为产品降级决定。后续按提案的门槛推进，不默认追加同类DNS实验、不删减能力或更改共享快照；框架、支持清单、组件采用与发布分别确认。
2. **P1设计进行中：首稿已形成，尚无正式写入实现。** [写入／本地事务设计](P1_LOCAL_DATA_DESIGN.md)已列业务不变量、命令／修订／回执／待同步的事务边界、18项保护样例及跨仓差异；首稿无正式契约版本，不修改只读0.1.0快照。下一项先与电脑侧核对金额录入／汇总边界、独立付款日与预约时区、身份／修订／幂等映射，形成双方固定版本与共同样例，再固化带版本的写入契约候选、正式事务接口及恢复设计；不直接实现写入／迁移。不能只靠当前汇总样例。覆盖全部现有目标能力，清单参考[电脑仓库接口能力矩阵](https://github.com/wuqiuwangtian/TravelFlow-AI/blob/main/docs/internal/MOBILE_CAPABILITIES.md)，逐项补齐LOCAL／MIXED本地规则，不擅自删掉高级工程、规划或回顾。
3. **P2／P3未开始：独立移动业务与安全直连。** 与电脑端分别交付，按约定协议验证离线写入、在线独立服务、配对、增量、重传与并发冲突；无常驻服务器、不加入云存储。不能直接同步活跃SQLite文件，也不默认同步密钥。
4. **P4／P5未开始：手机体验与集成验收。** 用户评审交互，覆盖真机权限／省电／升级和完整电脑规划→手机使用→直连→电脑复核。性能调查按用户要求暂缓。最终验收不能仅靠模拟器或构建通过。
